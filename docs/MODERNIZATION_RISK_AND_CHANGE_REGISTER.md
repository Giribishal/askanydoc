# AskAnyDoc modernization, risk, known-issue, and change register

**Effective date:** 2026-09-28

**Status:** active living register

**Authority:** this is the single current register for known technical risks, known limitations, modernization gaps, and planned application/infrastructure changes.

**Scope boundary:** it records work; it does not authorize a deployment, permission change, billing change, data migration, or destructive action.

## 1. How to use this register

- Add an entry only when it is supported by deployed configuration, a test, a trace, a measured result, or current primary documentation.
- Distinguish an observed failure from a design risk. Do not label every controlled or intentional failure as a defect.
- `Keep` means the current approach remains the baseline. `Update` means a bounded improvement is planned. `Defer` means retain the option until its trigger is measured. `Drop` means do not carry the idea forward.
- A reference architecture is a comparison baseline, not an automatic mandate. Any proposed replacement must improve a named requirement and preserve the understandable custom RAG baseline.
- Every infrastructure change still requires an exact plan, blast radius, cost, rollback, validation evidence, and fresh approval immediately before apply.
- Incident history remains in `ISSUES_AND_RESOLUTIONS.md`; SharePoint execution authority remains in `SHAREPOINT_RETRIEVAL_SOURCE_OF_TRUTH.md`; test evidence remains in `SHAREPOINT_REFERENCE_TEST_MATRIX.md`.

## 2. Current workload truth

- One React/CloudFront client calls a protected API Gateway HTTP API for authenticated SharePoint requests and a legacy public Lambda Function URL for AWS-only requests.
- One shared `askanydoc-api` Lambda owns routing, AWS retrieval, delegated SharePoint retrieval, Bedrock orchestration, validation, and citation assembly.
- AWS documents are ingested from S3 by a separate image-based Lambda into Aurora PostgreSQL/pgvector through the RDS Data API.
- SharePoint uses tenant-scoped Entra sign-in, API Gateway JWT validation, OBO delegated Graph access, site allowlisting, permission-trimmed Graph Search, and bounded on-demand PDF extraction.
- The deterministic source-classification fix was deployed on 2026-09-25. On 2026-09-28, the asynchronous answer package and bounded Aurora-resume recovery were deployed as Lambda code SHA-256 `31EBxNTHee98Nyhb+Ikv/6pFMvWf4jplV12uYwAeti4=`. A varied comparison began at 0 ACU and returned a browser-visible `organisation_sources` answer with five AWS disaster-recovery citations and three SharePoint hybrid-cloud citations.

## 7. Change-record template

For every future entry or status change, record:

1. observed evidence or current official source;
2. user/business effect and affected data path;
3. likelihood, impact, and whether the failure is intentional/acceptable;
4. `keep`, `update`, `defer`, or `drop` decision;
5. exact proposed code/infrastructure/IAM/data changes;
6. cost, security, downtime, and blast radius;
7. test and acceptance evidence;
8. rollback;
9. owner and review date;
10. approval record when mutation is required.
